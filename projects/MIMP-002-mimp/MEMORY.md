## Summary

MIMemoryLLMDb is a Git-based project memory system that lets AI assistants (Claude Code and others) share structured project knowledge across multiple machines. Each project gets a unique MIMP-XXX ID and a folder of markdown memory files in a private GitHub repository. A PowerShell CLI tool (`mimp`) handles syncing via push/pull/init commands. The format is plain markdown — any LLM can read it without special integrations. As of 2026-06-02 it also has a **Phase-2 brain layer** (`org/` + registry v2.0) that models the whole DHS business as entities → programs → projects — see [brain-layer.md](./brain-layer.md).

## Recent Changes

- 2026-09-04: **Scheduled unattended memory sync built (ADR-0009)** — `mimp scheduled-run [--dry-run]`, meant to be invoked by a daily Windows Scheduled Task (`tools/install-schedule.ps1`, run once per machine), replacing the fully-manual push workflow that had been silently losing updates. It pushes every registry project with `status: active` and a `local_paths.<thisMachine>` entry (read live off `registry.json`, so new registrations need no script edits), delegating each project's push to a child `mimp push <name>` process so one project's git failure can't abort the batch (preserves ADR-0007's fail-loud `Invoke-Git` per-project instead of weakening it). It also scans `~/.claude/projects/*/memory` for real (`MEMORY.md`-bearing) project memory not yet claimed by any registered project on this machine, and reports candidates — registration itself stays manual because `mimp init`'s entity/pillar/product classification is a judgment call (ADR-0006), never guessed. `tools/mimp-ignore.txt` (repo-committed, so it syncs to both machines) silences folders that will never be real projects. Every run logs to `~/.mimp-scheduled-run.log`; a push failure or a discovery candidate additionally raises a Windows toast (`System.Windows.Forms`, no new dependency) so it surfaces same-day instead of sitting unread in a log. Chose a fixed-time daily schedule (11pm on machineA) with Task Scheduler's `StartWhenAvailable` catch-up over a Claude Code `Stop` hook (rejected: per-project hook wiring vs. one machine-level schedule) or a filesystem watcher (rejected: needs a standing background process) — see ADR-0009 for the full tradeoff record, including why the task must run as **"only when user logged on"** rather than "whether logged on or not" (git's `wincred` credential helper is bound to the interactive session; the alternative would need the Windows password stored in Task Scheduler and risks silent credential-vault failures in a detached session — exactly the failure mode this feature exists to eliminate). Along the way, found and fixed a **pre-existing bug**: `mimp lint --json`/`--quiet` crashed with "parameter cannot be found" on this machine's PowerShell — the flags were compared as strings against `$Arg1`, but PowerShell's parameter binder rejects any unrecognized dash-prefixed token before that comparison ever runs; fixed by declaring them as real `[switch]` parameters (needed `[Alias('dry-run')]` for the new `--dry-run` flag, since PowerShell parameter names can't contain a hyphen). Verified end-to-end with `--dry-run` against the real registry and real `~/.claude/projects/` state: correctly identified all 6 active machineA projects to push and all 16 genuinely-unregistered project folders (of ~26 total), filtering out 2 known-junk folders (`C--WINDOWS-system32`, `c--Users-maidu`) via the ignore list. `mimp lint` stayed clean (3 pre-existing errors/6 warnings, all unrelated source-drift). **Not yet done — deliberately left for the user, since each has a real side effect:** the actual Windows Scheduled Task has not been registered on any machine yet (`tools/install-schedule.ps1` exists but hasn't been run for real), and no real (non-dry-run) `scheduled-run` has been executed. **Also discovered:** `git push` hangs indefinitely from this sandboxed Claude Code shell on machineA (confirmed via direct `git push`, not just via `mimp`) — `git pull --rebase` works fine and fast, so it's specifically push/write credentials that can't complete non-interactively here, consistent with the prior "mimp cannot do network git from PowerShell here" note below.
