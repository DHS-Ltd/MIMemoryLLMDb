  - **Pre-push review (2026-09-29), 5 parallel finder agents, found and fixed 3 real bugs before pushing** (commit `ed74917`, stacked on `aeb96c8`): (1) `extractUid()` called `decodeURIComponent` with no try/catch, outside the async handler's own catch — a malformed `%`-encoded UID (e.g. `/dicom-web/studies/1.2.3%/metadata`) threw an unhandled promise rejection that would've crashed the whole `pacs-backend` container on one external request, reachable the moment the gate left `off`; now caught. (2) The gate's patient-ownership check was a raw `study_uid`+`patient_id` match with no `claim_status` check, unlike every real patient route — a patient who used "report wrong study" (which sets `claim_status='under_review'` and revokes the study's links) could still pull raw pixels straight through `/dicom-web/`; now requires `claim_status='linked'`, matching `patient-portal.js`. (3) `decodeCookie()` ignored `ROLE_BOUND_TOKENS` entirely, unlike `requirePatient`/`requireDoctor`/`requireMt` (which only enforce the role match when that flag is `on`) — risked a silent partial-outage window for any pre-Phase-2 roleless session once the gate left `off`; now mirrors those middlewares exactly. 91/91 tests green (87 prior + 4 new regression tests for these 3 fixes). Also flagged but NOT code-changed (judgment calls, not bugs): any Postgres error fails the gate closed for every role including admin at once (arguably intentional fail-closed posture, but turns a DB blip into a platform-wide viewing outage — worth a deliberate decision before `on`); an already-open viewer tab 403s the instant the gate flips to `on` mid-session (inherent to any live cutover of a security control, not fixable without a grace mechanism); a few nginx/code duplication cleanups (lower priority, not security-relevant).
